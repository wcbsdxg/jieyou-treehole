# 解忧树洞 —— ESP32-S3 终端固件（基于 xiaozhi-esp32 修改）

> 高中生科技创新项目 · 老师优先 · 老师不在也能完整对话 · 录音不落盘

本固件在开源项目 [xiaozhi-esp32](https://github.com/78/xiaozhi-esp32)（v0.9.7，ESP32-S3 分支）的基础上修改而来：
保留其板级抽象（屏幕/按键/灯/音频/云端协议），应用逻辑**合并成一条完整链路**——
**老师端优先判定；老师没回复时，先本地安慰、再由小智云端把话完整说完**。

## 一、工作流程（单一合并逻辑）

```
待命 ──按住对话键──▶ 录音(16kHz/16bit WAV 仅存内存, 最长10秒)
                        │ 松开(或录满自动)
                        ▼
        ① UDP 分包发送到教师电脑（局域网，老师端判定）
                        │
                        ▼
   ┌───────────── 等待答复(三步走) ─────────────┐
   │ 0~1.5秒 : 屏显"等待回复..."                  │
   │ 1.5秒   : 老师还没回 → 本地安慰回复(暖橙灯)   │
   │ 4秒     : 老师还没回 → 小智云端接管：          │
   │           上传这段录音→云端识别→组织回答→      │
   │           回传语音+文字，边播边说(绿灯)        │
   │ 15秒    : 老师仍未回 → 以已给出的回答为准      │
   └──────────────────────────────────────────┘
                        │ 老师在15秒内回复则一律优先
                        ▼
   屏幕显示 text + 12颗RGB灯呼吸
   ├─ 绿级: 绿色呼吸, 仅屏显+灯效
   ├─ 黄级: 黄色呼吸, 仅屏显+灯效
   ├─ 红级: 红色呼吸 + 屏显 12355 热线/心理老师电话 + 播放求助提示音(Flash内置8kHz WAV)
   ├─ 云端: 绿色呼吸 + 小智的完整回答(文字上屏 + 语音播报)
   └─ 本地: 暖橙呼吸 + 陪伴式安慰语(不判定级别, 机器不替老师下结论)

老师也能主动说话 ──▶ 老师端点「🎤 录音发语音」
   └─ 终端收到后: 蓝色呼吸 + 屏幕"老师在跟你说话..." + 用喇叭播出老师的声音
      (待命/显示结果/等待回复/云端回答这几个阶段都收; 老师的话比云端回答优先,
       播完自动恢复原来的画面)
```

时间参数都在 `main/application.cc` 顶部：
`LOCAL_REPLY_DELAY_MS`（1500）、`CLOUD_FALLBACK_DELAY_MS`（4000）、`REPLY_TIMEOUT_MS`（15000）、
`CLOUD_ANSWER_TIMEOUT_MS`（25000），以及总开关 `ENABLE_CLOUD_FALLBACK`（1=开启云端兜底，0=纯局域网）。

### 云端兜底（小智）说明

- 只有"老师没回复"时才会走云端；老师端链路全程只在局域网内。
- 云端兜底需要设备能上外网，且该设备已在小智控制台完成激活
  （未激活时云端会下发提示语，屏幕会直接显示，不会让学生干等）。
- 走云端时这段录音会上传 `api.tenclass.net`（与小智音箱同款行为）。
  **如果项目要强调"语音不出校园"，把 `ENABLE_CLOUD_FALLBACK` 改为 0 即可**，
  此时行为是：本地安慰语 + 老师端判定（完全局域网）。
- 通信协议默认走 Websocket（与厂商原版固件一致），menuconfig → `Connection Type` 可切换。

## 三、构建方法（Windows / ESP-IDF 5.3 ~ 5.4）

1. 按上游 README 安装 [ESP-IDF **v5.3 或 v5.4**](https://docs.espressif.com/projects/esp-idf/zh_CN/latest/esp32/get-started/)（一键安装器选 ESP32-S3 支持）。
   > ⚠️ **不要用 ESP-IDF v6.x**：本工程依赖的组件（`78/esp-opus-encoder`、`78/esp-ml307` 等）
   > 都声明了 `idf: ^5.3`，v6.x 下组件管理器会直接报
   > `ERROR: Version solving failed: … depends on idf (^5.3)`，配置阶段就停下。
   > 实测（本机 ESP-IDF v6.1）：换 v5.3/v5.4 即可正常编译。
2. 打开 ESP-IDF 终端，进入本目录：
   ```bat
   idf.py set-target esp32s3
   idf.py menuconfig
   ```
   在 menuconfig 里确认两项（都已是默认值，一般不用改）：
   - `Xiaozhi Assistant → Board Type` → **解忧树洞 MAG AI 1688 Mini (ESP32-S3)**
   - `Xiaozhi Assistant → Connection Type` → **Websocket**（与厂商原版固件一致的云端通道）
   另确认 `Component config → ESP PSRAM → Support for external, SPI-connected RAM` 为开启、
   Mode 为 Octal（sdkconfig.defaults.esp32s3 已配好 N16R8 的 Octal PSRAM，通常无需手动改）。
3. 编译：
   ```bat
   idf.py build
   ```
4. 烧录（按住板上 BOOT 键插 USB，松开后执行）：
   ```bat
   idf.py -p COMxx flash monitor
   ```

### 第一次使用前必改

- `main/application.cc` 顶部宏：`TEACHER_TEXT`（心理老师真实联系方式）

## 四、UDP 协议（终端 ↔ 教师端）

> 教师电脑上要跑的程序在 **`F:\talk robot\teacher\`**（`server_gui.ps1` PowerShell 图形界面版 /
> `server.py` Python 图形界面版，两套功能等价；同目录还有模拟终端脚本 `test_device.py`、
> `test_voice_recv.py` 与部署说明 `README.md`）。下面是与它约定的协议细节。
> 教师端右上角有 **⚙ 设置**：学生机器人地址、监听端口、回复有效期、**回复语库**
> （绿/黄/红各 10/10/8 条，可增删，主界面下拉框自由挑选）、**老师录音用的麦克风**等
> 都在界面里调，存到教师端目录的 `config.json`（PowerShell 版 `server_gui.ps1` 与 Python 版共用同一份配置）。
> 老师还能点主界面的 **🎤 录音发语音**，把自己说的话发到终端喇叭里（协议见下）。

**终端 → 服务端**（发到 SERVER_IP:SERVER_PORT，本机源端口 = LOCAL_PORT）：

```
每包 = 魔数"XZSD"(4字节)
     + 序号(2字节, 大端, 从0开始)
     + 本包数据长度(2字节, 大端)
     + 标志(1字节, bit0=1 表示最后一包)
     + 数据(≤1200字节)
```
第 0 包的数据以 44 字节 WAV 文件头（"RIFF"开头）开始；按序号把数据拼接即为
完整的 16kHz/16bit/单声道 WAV 文件，可直接保存播放。

**服务端 → 终端**（回发到来源 IP:来源端口，即终端的 LOCAL_PORT）：

单包 UTF-8 JSON（≤ 1024 字节）：
```json
{"level":"green","text":"你听起来状态不错，继续保持！"}
{"level":"yellow","text":"最近压力有点大？可以找我聊聊。"}
{"level":"red","text":"别怕，我在这里陪你。"}
```

**服务端 → 终端 · 老师语音**（老师点 🎤 录音，发到终端 IP:LOCAL_PORT）：

```
每包 = 魔数"XZSV"(4字节)
     + 序号(2字节, 大端, 从0开始)
     + 本包数据长度(2字节, 大端)
     + 标志(1字节, bit0=1 表示最后一包)
     + 数据(固定 1200 字节, 最后一包除外)
```
内容是一段完整的 **8kHz/16bit/单声道 WAV**（带 44 字节头），从第 0 包第 1 个字节开始切。
终端按 **"序号 × 1200" 直接落到 `teacher_buf_`** 的对应位置，所以**包到得顺序乱了也没关系**；
收到"最后一包"就认为收齐并立刻播放（蓝灯呼吸）。

> **落位规则**：老师发来的就是一份完整 WAV（第 0 字节是 `R`），终端把它**原样落在
> `teacher_buf_` 的开头**（不加偏移）；播放时用通用播放器 `PlayWavBuffer()`，
> 它会自己从偏移 0 校验 `RIFF`/`WAVE`、偏移 24 读采样率、偏移 40 读音频长度。
> （曾经把数据落在 `+44` 想"给头部留位置"，结果播放器读到未初始化内存判"数据无效"，
> 老师语音一帧都播不出来 —— 已修。）

**长度上限**：`VOICE_MAX_BYTES = REC_BUF_SIZE = 320000` 字节，指的是**整段 WAV 的总长**
（含 44 字节头），所以音频部分最多 319956 字节 ≈ **19.99 秒**。
超过这个总长，固件会判定"超出缓冲"并把**整段**丢掉（一帧都不播），
所以两个教师端都会先截断到 320000 总长再发（同时改掉 WAV 头里的两个长度字段）。
设置里的"最长录音"默认 8 秒，可调到 20 秒。

> 老师在**学生按住说话的这 10 秒里**发的语音也不会丢了：终端在这期间会
> "只收不播"地把分片攒进缓冲（播放会打断录音），等学生松手、语音发出去之后，
> 先播老师的这段话，再开始算 15 秒的等待窗口。

> 终端是单片机，固件主循环约 30 毫秒跑一轮，**老师端每发 4 个包会自动歇 20 毫秒**；
> `sdkconfig.defaults` 里也把 `CONFIG_LWIP_UDP_RECVMBOX_SIZE` 从默认 6 放宽到 32。
> 如果改过 `sdkconfig.defaults`，先删除旧 `sdkconfig`（或执行 `idf.py fullclean`）再编译，否则旧缓存可能继续保留原值。
> 这两条都是实测踩坑后加的：不加限速时一次连发 107 个包会丢 72 个（听起来断断续续）。

**回复时序约定（重要）**：
- 终端发出后 **1.5 秒**内没收到回复 → 先显示本地安慰语（暖橙灯），继续等；
- **4 秒**仍没收到 → 交给小智云端完整回答（绿色灯，文字上屏 + 语音播报），
  此期间老师端回复到了会**立刻改用老师的判定**（老师始终优先）；
- **15 秒**仍没收到 → 以已经给出的回答为准，状态栏提示"老师稍后会回复你"；
- 老师端（服务端）不必抢时间，只要在 15 秒内回就是权威判定；
  如需更久，调大 `main/application.cc` 的 `REPLY_TIMEOUT_MS`。

## 五、求助提示音（红级播报，可换音色/换成真人录音）

**默认音色**：极轻的"叮——咚"两声（**C5 → G5**，2.44 秒，峰值 **-11.7 dBFS**）。
设计目标就四个字：**别吓着人**——每声都是"低次泛音 + 指数衰减"的柔和音色（高频泛音已砍掉），
**35ms 软起音 + 开头 12ms 渐入 + 结尾渐弱**，所以听感是"轻轻响一下"，不是那种一激灵的"叮！"。

想先试听：先把电脑音量调到 **30% 左右**，再双击 `main/assets/help.wav`
（早期那版峰值拉满 -3 dBFS，电脑上直接播放会很响——现在整体轻了约 4 倍）。

### 换音色（5 种内置预设，全部都是"轻"的）

```bat
cd tools
node gen_help_wav.js                      :: 默认 gentle: C5→G5 两声, 最温和
node gen_help_wav.js tiny                 :: 更轻: 只有一声"叮" (自习环境推荐)
node gen_help_wav.js soft                 :: A4→C#5→E5 三声, 慢而柔
node gen_help_wav.js harp                 :: 竖琴式五音上行(稍亮)
node gen_help_wav.js chime                :: C5→E5→G5→C6 明亮版
node gen_help_wav.js gentle 我的.wav 0.2   :: 第3个参数=音量(峰值0~1), 0.2 更轻
```
`tools/presets/` 里已放好 `help_tiny / help_soft / help_chime / help_harp` 四个现成文件，
想换哪个就把它改名成 `help.wav` 覆盖到 `main/assets/`，再 `idf.py build flash`。
生成器每次都会打印**峰值/响度/起音/跳变体检/音量包络**，一眼就能看出"会不会吓人"。

| 音色 | 峰值 | 时长 | 感觉 |
|---|---|---|---|
| gentle（默认） | -11.7 dBFS | 2.44 秒 | 轻轻两声，最推荐 |
| tiny | -13.2 dBFS | 1.60 秒 | 只有一声，最安静 |
| soft | -11.1 dBFS | 2.92 秒 | 三声慢速，柔和 |
| chime | -10.5 dBFS | 2.76 秒 | 四声明亮，仍比最早的"哔哔"轻得多 |
| harp | -10.5 dBFS | 2.18 秒 | 五音上行，像风铃 |

### 换成真人录音（推荐答辩时用）

1. 用 Audacity 等本地工具录一段温和的提示（如"同学别怕，我在这里陪你，需要的话请拨打 12355……"）；
2. 导出为 **WAV / 8000 Hz / 16-bit PCM / 单声道**（导出后把音量压到 -12 dBFS 左右更稳妥）；
3. 覆盖 `main/assets/help.wav`，重新 `idf.py build flash`。

> **音量怎么调**：实际播报音量 = 终端音量设置（默认 70%，按音量 +/− 键可调）× 文件本身响度。
> 提示音**故意做轻**，是为了不吓到本来就紧张的同学；觉得偏轻就按音量键加大，
> 而不是把文件峰值抬高（抬高了容易削波、变难听）。

## 七、隐私与安全说明

- **老师端链路**：全程只在局域网内（UDP 到教师电脑），不含任何公网调用；
- **云端兜底**：只有"老师没回复"时才会连 `api.tenclass.net` 让小智回答，
  此时这段录音会上传云端（与小智音箱同款行为）；
  **要保证"语音不出校园"，把 `main/application.cc` 的 `ENABLE_CLOUD_FALLBACK` 改为 0**，
  行为即变成"本地安慰语 + 老师端判定"，完全局域网；
- 云端版本检查只做校验与激活，**不会自动升级固件**（避免定制固件被官方固件覆盖）；
- 录音缓冲始终在内存(PSRAM)中，发送完即被下次录音覆盖，断电即消失，不写 Flash；
- 串口日志只输出状态信息（IP、录音秒数等），不输出音频数据。

## 八、常见问题

| 现象 | 处理 |
|---|---|
| 屏幕白屏/花屏 | 确认 8080 数据线顺序与 config.h 一致；尝试把 `mag_ai_board.cc` 中 `pclk_active_neg` 置 1 |
| 屏幕颜色反了(偏紫) | `mag_ai_board.cc` 的 `swap_color_bytes` 取反再试 |
| RGB 灯颜色不对(绿变红) | `application.cc` 里 `LED_PIXEL_FORMAT_GRB` 改为 `LED_PIXEL_FORMAT_RGB` |
| 录音无声/沙沙声 | 检查麦克风 L/R 脚是否接地(左声道)；确认 mic_sck/mic_ws 接线 |
| 功放无声音 | NS4168 的 CTRL 脚应上拉(原板已接)；确认 BCLK/LRCLK/DATA 三线 |
| 屏幕只显示一部分 | 个别批次屏为 240x284，把 `config.h` 的 `DISPLAY_HEIGHT` 改为 284 |
| 构建报 PSRAM 相关错误 | menuconfig 里 ESP PSRAM 选 Octal、并确认芯片为 N16R8 |
| 老师还没回就出现橙色安慰语 | 正常行为(本地安慰)，想等更久再安慰就调大 `LOCAL_REPLY_DELAY_MS` |
| 老师不在时小智回答了，但很慢 | 云端要"上传→识别→生成→回传"，通常 2~5 秒；可调 `CLOUD_ANSWER_TIMEOUT_MS` |
| 小智一直说"联系不上" | 检查设备能否上外网；设备需在小智控制台激活（云端提示语会显示在屏幕上）；也可调 `ENABLE_CLOUD_FALLBACK 0` 只用本地 |
| 不想让语音上传云端 | `application.cc` 顶部 `ENABLE_CLOUD_FALLBACK` 改为 0，重新编译 |
| 老师回复超过15秒才到，屏幕没更新 | 超时后终端已结束等待；调大 `REPLY_TIMEOUT_MS` 即可（如 30000） |
| 老师发语音，终端没声音 | ① 固件是否为这份改过的版本（原版不认 `XZSV`）；② 串口日志看有没有「老师语音收齐: N 字节(实收 N)」；③ 老师端点了「🎤 录音发语音」后，**再点一下只是结束录音**，必须在「待确认」窗点 **发送** 才会发出；④ 学生正按住对话键时终端在录音，等他说完再发 |
| 老师的声音断断续续/只播半句 | 缺一个分片就整段不播：串口会先出现「老师语音等待末包超时, 已丢弃 N 字节」（`application.cc:1172-1174`），终端同时回否认确认，教师端显示「终端拒绝了这个语音…」或「等待超时…」。**别只看"是不是 WiFi 丢包"**：教师端每 4 包歇 20 毫秒限速与 `sdkconfig.defaults` 的 `CONFIG_LWIP_UDP_RECVMBOX_SIZE=32` 都只是**降低**丢包概率、**不保证送达**，所以不能断言"靠近路由器/重录一次一定解决"，其它原因（教师端发包失败、固件版本旧、缓冲被上一段占着）也要一起看 |
| 串口日志里找不到「老师语音疑似丢包(N/M)」 | 这句**旧文案在当前固件里不存在**，已删除。真实文案只有三句：`老师语音收齐: N 字节(实收 N)`（`:1359`）、`老师语音播放完毕`（`:1226`）、`老师语音等待末包超时, 已丢弃 N 字节`（`:1172`） |
| 老师的声音听起来像电话 | 正常：终端喇叭链路固定 8kHz（`AUDIO_OUTPUT_SAMPLE_RATE`），老师端会自动把麦克风采样率重采样到 8kHz |
| 想固定播一段录音（不用现录） | 把 8kHz/16bit/单声道 WAV 用 `EMBED_FILES` 打进 Flash、仿照 `PlayHelpAudio()` 播放即可（`help.wav` 就是现成例子） |
